# Обязательные правила проекта «Поварня»

## Формат версии — без исключений

- Каноническая версия приложения имеет только вид `0.x.y`, где `x` и `y` —
  неотрицательные целые числа не больше 999, одновременно не равные нулю.
  Ведущие нули запрещены.
- Строка `version:` в `pubspec.yaml` обязана целиком соответствовать шаблону
  `0.x.y`. Суффиксы, метаданные сборки и предварительные версии запрещены.
- Никогда не записывайте и не показывайте версию как `0.x.y+N`. Запрещено
  добавлять `+build`, `versionCode`, номер CI-сборки или иной четвёртый
  компонент в исходники, интерфейс, журнал, документацию и имена выпусков.
- Git-тег выпуска имеет вид `v0.x.y`; имя GitHub Release и `versionName` APK —
  `0.x.y`.
- Не передавайте Flutter параметр `--build-number` и не добавляйте номер после
  знака `+` в `pubspec.yaml`.
- Внутренний Android `versionCode` не является частью версии. Он вычисляется
  сборкой из `0.x.y` по формуле `x * 1000 + y` и может упоминаться только как
  отдельное техническое поле без присоединения к строке версии.
- При любом изменении механизма версий синхронно обновляйте парсер обновлений,
  тесты и документацию. Нельзя ослаблять `test/version_format_test.dart`.
- Перед завершением задачи убедитесь, что в проекте нет строк формата
  `0.x.y+N`, а полный набор тестов проходит.
